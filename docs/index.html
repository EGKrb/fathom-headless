What's in the box

The same engine build as Fathom, with everything that works without a GUI.

x64 and x32 engine

headless.exe, x64dbg.dll / x32dbg.dll, TitanEngine, GleeBug — every x64dbg command, script and expression.

TraceExport

Record execution traces and export them to JSON, CSV, or Tenet / Frinet to explore them in IDA Pro, or .ftt to walk them backward with the tt.* commands.

Plugins

pybridge (Python), ExtraCmds, ScyllaHide, xAnalyzer, plus PE-sieve and the HvKdFusion / wineye scripts.

Templates

Twelve ready-made scripts — API logging, unpacking dumps, pattern search, traces — and a launcher with isolated settings.

Quick start

Windows 10 / 11. No installer: extract and run.

  1. Download fathom-headless_1.2.0.zip.
  2. Extract it into a folder you can write to, e.g. C:\Tools\fathom-headless.
  3. Run a template, or your own script:
cd C:\Tools\fathom-headless
.\run-headless.ps1 -Template api-log -Target C:\Windows\System32\whoami.exe
.\x64\headless.exe -cf C:\work\trace.txt

Use x64\headless.exe for 64-bit programs and x32\headless.exe for 32-bit ones. Numbers in commands are hexadecimal by default (.100 = 100).

Four ways to drive it

All of them run the same commands as the x64dbg command bar.

Script

headless.exe -cf script.txt runs a script at startup, then keeps reading commands from standard input.

Interactive

Type init, bp, run, StepOver, log... on standard input — locally or over SSH.

Templates

run-headless.ps1 -Template <name> -Target <exe> fills a template and collects the results in out\.

Python

Debugger.launch(r"C:\Tools\fathom-headless") with pybridge: breakpoints, memory, registers from Python.

// trace.txt
init "C:\samples\target.exe"
StartTraceRecording "C:\work\trace.trace64"
TraceIntoConditional 0, .2000
StopTraceRecording
TraceExport "C:\work\trace.trace64", "C:\work\trace.json"
TraceExport "C:\work\trace.trace64", "C:\work\trace.log", tenet
TraceExport "C:\work\trace.trace64", "C:\work\trace.ftt", ftt

Templates

%TARGET%, %MODULE%, %OUT% and %BITS% are filled in by the launcher.

TemplatePurpose
api-log, hook-apis-extendedlog API calls with their arguments, without pausing
trace-export, run-tracerecord a trace from the entry point and export JSON / CSV / Tenet / .ftt
hook-unpack, unpack-dumpfollow runtime unpacking and dump the region flipped to executable
dump-module, dump-at-delaysave the main module and a full minidump
break-on-fileconditional breakpoint on a file open, then automatic actions
antidebughide the debugger and log anti-debug probes
find-patternsearch a hex or ASCII pattern over the whole memory map
emulate-dumpemulate a .dmp and serve it to pybridge

Good to know

A debugger writes into the memory of the process it debugs, which antivirus behaviour monitors can take for injection: for malware analysis, work in a VM with an exclusion for the package folder. Use it on programs you are allowed to analyse.
